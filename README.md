# HdrPlayer

基于 libmpv 的本地视频播放器，界面用 WPF + [WPF-UI](https://github.com/lepoco/wpfui)（Fluent 风格，深色 + Mica）。
HDR 输出按显示器自己上报的参数（峰值亮度等）做色调映射，显示器不支持 HDR 时自动映射到 SDR。

## 运行

**安装版**：从 Release 下载 `HdrPlayer-<版本>-win-x64-setup.exe`，不需要管理员权限，安装包已带 libmpv（也需要下面第 1 步的 .NET 运行时）。
安装时会列出所有支持的视频后缀，逐个勾选要用 HdrPlayer 打开的；所有后缀都会出现在右键“打开方式”里。`.ts` 默认不勾，因为 TypeScript 源文件也用这个后缀。
**一键设为默认播放器**：安装完成页勾选“一键设为默认播放器”（或以后在 全局设置 → 操作 → “一键设为默认”），确认一次管理员权限，**注销并重新登录（或重启）**后，勾选的后缀就全部用 HdrPlayer 打开，不用在 Windows 设置里逐个后缀点。
原理：Windows 10/11 不允许程序直接写用户的默认程序选择（带系统校验，新版 Windows 11 还换成了带机器标识的 UserChoiceLatest），这里用的是微软给企业管理员的正规机制——组策略“设置默认关联配置文件”（`HKLM\SOFTWARE\Policies\Microsoft\Windows\System\DefaultAssociationsConfiguration` 指向 `C:\ProgramData\HdrPlayer\DefaultAssociations.xml`），由 Windows 自己在登录时应用。不伪造系统校验，所以不怕系统更新改算法。
注意：策略生效期间，每次登录 Windows 都会把这些后缀恢复成 HdrPlayer；想换回别的播放器，先在设置里点“取消”（卸载时也会自动撤销）。微软官方只支持专业版 / 企业版 / 教育版，家庭版可能无效，可改用设置里的“打开默认应用设置”手动设置。
要增删后缀，改 `installer/gen_iss.py` 里的列表后重新生成 `HdrPlayer.iss`。

**便携版 / 自己编译**：

1. 安装 **.NET 8 Desktop Runtime (x64)**：https://dotnet.microsoft.com/download/dotnet/8.0
2. 下载 libmpv：https://github.com/shinchiro/mpv-winbuild-cmake/releases
   选最新的 `mpv-dev-x86_64-v3-*.7z`，解压出 **`libmpv-2.dll`**，放到 `HdrPlayer.exe` 同一目录。
   （libmpv 要用 2025 年及以后的版本，否则杜比视界 Profile 检测、HDR10+ 属性等功能可能缺失。）
3. （可选，自动同步字幕和修复视频用）`pip install ffsubsync`，并把 ffmpeg / ffprobe 放进 PATH；或者从发布版里拷 `tools\` 目录过来。
4. 运行 `HdrPlayer.exe`。也可以把视频文件拖到 exe 上，或设为默认打开方式。

## 自动构建

推送 `v` 开头的标签（或在 GitHub 网页上新建 Release 时创建新标签）会触发 GitHub Actions：
编译、下载最新的 libmpv-2.dll（shinchiro/mpv-winbuild-cmake），用 PyInstaller 把 ffsubsync 打包成 exe、下载 ffmpeg（BtbN/FFmpeg-Builds，LGPL 版，自动同步字幕和修复视频共用），一起放进 `tools\`，打包成便携版 `HdrPlayer-<版本>-win-x64.zip` 和安装程序 `HdrPlayer-<版本>-win-x64-setup.exe`（Inno Setup，脚本在 `installer/`），上传到该 Release。

```
git tag v0.3.0
git push origin v0.3.0
```

标签带 `-`（如 `v0.3.0-beta`）会发成预发布。

每次构建完成后，如果仓库配置了 R2 密钥，会把安装程序传到 Cloudflare R2 的 `hdrplayer-release/releasefile/HdrPlayer-setup.exe`（覆盖旧的），并更新同目录的 `latest.json`（版本号、构建号、SHA-256、大小），程序里的“检查更新”读的就是它。需要的配置（仓库 Settings → Secrets and variables → Actions）：

| 名称 | 类型 | 内容 |
|---|---|---|
| `R2_ACCESS_KEY_ID` | Secret | R2 API 令牌的访问密钥 ID（对象读和写，只限这个存储桶） |
| `R2_SECRET_ACCESS_KEY` | Secret | R2 API 令牌的机密访问密钥 |
| `R2_PUBLIC_URL` | Variable | 存储桶的公开访问地址，如 `https://pub-xxxx.r2.dev` 或自定义域名 `https://cdn.example.com`（必须 https，末尾不带 `/`），编译时写进程序，用来检查和下载更新 |

**换更新域名**：改 `R2_PUBLIC_URL` 后只有**之后编译**的版本用新域名；已经装好的旧版本里写死的是旧地址。所以旧地址（如 r2.dev 公开访问）要先保留，等旧版本都通过它更新到新构建以后再关。两个地址指向同一个存储桶，不用重复上传。

也可以在 Actions 页面手动运行，只生成构建产物、不发布。

## 从源码编译

```
dotnet build -c Release
```
把 `libmpv-2.dll` 放到项目目录，编译时会自动复制到输出目录。

## 功能

| 需求 | 实现 |
|---|---|
| HDR10 | mpv `vo=gpu-next` + D3D11，输出 PQ/BT.2020，按显示器 EDID 峰值做色调映射 |
| HDR10+ | 检测到动态元数据后，自动改用 ST 2094-40 曲线并关闭逐帧峰值检测 |
| 杜比视界 | 默认保留 RPU，由 gpu-next（libplacebo）按逐帧动态元数据重塑 + 色调映射，**Profile 5（IPTPQc2）也能正确播放**，P8.1 / P8.4 / P7 同样适用。设置里可改为“剥离 RPU”只播放基础层（此时 P5 会提示不兼容） |
| 解码 | 默认 D3D11VA 硬解（全局设置）；右键 → 解码方式（本视频）可以给单个视频另选，按文件记住，优先于全局设置；显卡不支持的格式（如 H.264 10-bit / Hi10P）自动改用软解，硬解中途连续出错也会回退。软解线程数可在设置里改，默认自动（按逻辑核心数，最多 16） |
| 音频直通 | 全局设置 → 音频 →“音频直通”（默认关）：AC3 / E-AC3 / DTS / DTS-HD / TrueHD 不在本机解码，拆封装后原样以 HDMI 码流（mpv `audio-spdif`）发送给功放或电视解码；这时下混、防削波、音量调节都不起作用，设备或音轨格式不支持时自动改为正常解码。真正在直通时（按 mpv 实际的输出格式判断），控制栏去掉音量条，静音按钮显示“有声音”的灰色图标、点不动（本机没法发合法的静音帧，静音交给功放 / 电视），M、↑ / ↓、滚轮只提示“音量和静音由功放 / 电视控制”。每个视频可以在画面右键 →“音频直通”里直接开关，按文件记住（和全局设置一致时就回到跟随全局）；当前音轨的格式不能直通（AAC、FLAC、Opus 等）时这一项是灰的并写明格式，格式能直通、但 mpv 打不开直通输出（Windows / 驱动不接受这种码流）时，mpv 自己退回正常解码：提示一次，按正常解码套上下混和防削波（防削波策略可选），菜单里这一项不再显示开启，但仍可点击，点一下就是再走一遍直通流程。码流发出去了但功放 / 电视解不了的情况，播放器这边检测不到，仍显示为直通。直通开着但音轨是 AAC 这类不能直通的格式时，也按正常解码处理（下混、防削波照常生效）。视频参数（I）里能看到实际有没有直通 |
| 5.1/7.1 → 立体声 | `audio-channels=stereo`（libswresample 标准下混矩阵），不做系数归一化（那样整轨都会变小声） |
| 防削波 | 全局设置 → 音频 →“防削波策略”：**仅限幅**（默认）用 `alimiter` 只把超过满幅的峰值压到 −0.2 dBFS 以下，其它地方不动，保留动态范围；**拉平音量 + 限幅**先用 `dynaudnorm` 把大声和小声拉得更接近（对白更清楚，适合夜里看），再限幅。下混到立体声时先在滤镜链里下混好再接这些处理（mpv 默认在所有滤镜之后才下混，限幅器会看不到下混后的过冲）。每个视频可以在画面右键 →“防削波（本视频）”里单独选（跟随全局设置 / 仅限幅 / 拉平音量 + 限幅），按文件记住；跟随全局的视频随全局设置变 |
| 自动 HDR | 空着启动播放器**不会**改动 Windows 的 HDR 开关；打开 HDR 片源（HDR10 / HDR10+ / HLG / 杜比视界，包括通过“打开方式”直接启动）时自动开启 HDR 输出并打开 Windows 的“使用 HDR”；SDR 片源自动关闭。切换期间短暂暂停，纯音频和带封面的音乐文件不触发切换。退出时把 Windows HDR 还原为启动前的状态。设置里关掉“由软件自动管理系统 HDR 开关”则只手动切换。显示器不支持 HDR，或系统策略不允许（例如笔记本用电池）时，不切换、保持 SDR 输出，HDR 片源色调映射到 SDR，并在画面上提示原因（手动按 H 也一样） |
| 自动匹配刷新率 | 打开播放器时不动；开始播放时按视频帧率把显示器切到整数倍的刷新率，例如当前 60 Hz、视频 25 帧 → 50 Hz，23.976 帧 → 71.928 Hz。刷新率不低于 47.952 Hz（24 / 25 / 30 帧至少 ×2）。恰好整数倍的优先，没有就用最接近的（误差 0.5% 以内，例如 119.88 帧用 120 Hz）；当前刷新率已经匹配就不切，否则选符合条件的最低刷新率（越高越耗电，看视频用不上）。只在系统列出的刷新率里选（EDID + 显卡驱动给出的模式，包括在显卡控制面板里加过的；精确值通过 DXGI 读取），不设置自定义刷新率。切换视频时重新匹配，匹配不到就恢复原来的；切换时短暂暂停；退出时还原。只是临时修改，不写进系统设置，万一程序崩溃，注销或重启后也会恢复。全局设置 → 视频 里可关闭：关掉后始终不改显示器刷新率，只看当前刷新率是否匹配 |
| 视频同步 | 刷新率和帧率匹配（恰好或足够近似的整数倍）时，一律按显示器刷新率重采样（mpv `display-resample`）：mpv 微调播放速度（最多 1%）把那点差别补上，例如 72 Hz 播 23.976 帧也不会每隔十几秒重复一帧。匹配不上时（找不到合适的刷新率，保持原来的）按全局设置 → 视频 →“视频同步”选的策略：按音频同步（默认），或帧插值（平滑顿挫，画面会有轻微的帧混合；mpv 的插值要求按显示器同步，所以同时按显示器刷新率重采样）。每个视频可以在画面右键 →“视频同步（本视频）”里单独选（跟随全局设置 / 按音频同步 / 帧插值；跟随全局设置的视频，全局设置改了也跟着改），按文件记住，优先于全局设置；刷新率已匹配时这一项是灰的，显示“视频同步（刷新率已匹配）”。视频参数（I）里可以看到当前用的是哪种 |
| 随时开关 HDR | 快捷键 H / 控制栏按钮 / 右键菜单，同样会切换 Windows 的“使用 HDR” |
| 读取屏幕参数 | 运行时通过 DXGI `IDXGIOutput6::GetDesc1` 读取 EDID 的峰值/全屏亮度、原色等（跑过“Windows HDR 校准”则是校准后的值）。Windows 处于 HDR 模式时按读到的峰值做色调映射（高光压缩到屏幕能显示的范围），低峰值屏也照实用；还没切到 HDR 时暂用 1000 nit，切换完成后重新读取。设置里可手动指定 |
| HDR 开关接口 | Windows 11 24H2 起用新接口（`GET_ADVANCED_COLOR_INFO_2` / `SET_HDR_STATE`），把 HDR 和“自动颜色管理”（SDR 屏上的 WCG）区分开，不会把开着 ACM 的 SDR 屏当成 HDR；旧系统自动退回旧接口 |
| 窗口大小 | 第一次启动按当前屏幕大小（含缩放）取 3/4，视频区域 16:9；之后记住手动调整的大小和位置 |
| 字幕 | 拖到画面上即可加载；Z/X 或右键菜单调整延迟（按字幕记忆：同一个视频的不同字幕各记各的；关闭字幕时 Z/X 只提示“当前无字幕或为硬字幕”）；设置里可选字体（列出已安装字体）、字号、自动加载规则；首选音轨 / 字幕语言可从下拉框选（简体 / 繁体中文找不到时互相替代，再找不到用英语；其它语言找不到用英语），或手动输入语言代码列表（严格按顺序匹配，全角 / 半角逗号均可） |
| 自动同步字幕 | 右键 → 字幕延迟 → **自动同步字幕（ffsubsync）**：用 [ffsubsync](https://github.com/smacke/ffsubsync) 按当前音轨的人声对齐当前字幕（整体偏移 + 帧率差，如 23.976↔25），生成“原名.synced.srt/ass”并自动切换过去，原文件不动；内嵌的文字字幕会先提取出来再同步，没选字幕时让你选一个文件。GBK 等编码自动识别，输出 UTF-8；ASS 样式保留。同步期间画面上显示进度，同一菜单项可取消。图形字幕（PGS / VobSub）不支持 |
| 播放列表 | 侧边栏（P），拖入的视频会加入列表；退出时保存，下次启动时恢复（空着启动只恢复列表、不自动播放），覆盖安装 / 升级后也保留。每项显示缩略图（上次退出 / 切走时那个位置的画面，没看过的取片长 10% 处；后台另开一个不出画面的 mpv 生成，缓存在 `%LOCALAPPDATA%\HdrPlayer\thumbs`，打开播放列表时才生成），文件名自动换行（最多 3 行，再长就在末尾显示 …，鼠标悬停看完整路径），文件名下方（和缩略图底边对齐、和文件名左对齐）显示上次的进度 / 片长（00:00:00/00:00:00，切走、退出时更新），正在播放的一项显示“播放中”，文字用强调色。Ctrl / Shift 可以多选，选中多项时右键只有“移除”；右上角“取消选中”按钮清除选择。打不开的文件会标出来，右键可以修复。软件获得焦点、加载播放列表时检查文件还在不在（后台检查，不卡界面）：找不到的文件右上角显示红色圆圈感叹号，悬停提示“找不到此视频”，右键只有“移除”和“打开原先所在目录”（原来的文件夹也没了就打开还在的上一级）；恢复上次的播放列表时找不到的文件也保留，方便看出是哪些 |
| 修复视频 | 右键 → **修复视频（重新封装）**，播放列表里右键某个文件也有：先用 ffprobe 快速检查（文件头、时长、扩展名和实际格式、开头 30 秒的时间戳和数据包、能否跳到结尾附近，一般几秒），看起来正常就先提示“这个文件看起来是正常的”，仍然要修再继续；发现问题会在确认框里列出来。然后用 ffmpeg 不重新编码地重新封装成“原名.repaired.mkv”（画质不变，原文件不动，速度主要取决于硬盘），完成后在播放列表里替换原文件，正在播放的接着原来的进度播放。能修好：拖不动进度条、时长不对、时间戳错乱导致的音画不同步或卡住、电视录像（TS）里的坏包、扩展名和实际格式不符。修不好：画面本身花屏 / 马赛克，以及录制中断、缺少索引（moov）的 MP4 / MOV（会明确提示）。画面右键菜单里的修复针对正在播放的文件；格式无法识别、根本打不开的文件（可能不止一个）在播放列表里右键修复，修好后如果当时没在播放别的，会直接开始播放。MP4 的文字字幕转成 SRT；MKV 放不下的流（时间码等数据流）省略 |
| 只开一个窗口 | 已经在运行时，在资源管理器里双击视频不会再开一个窗口：文件加到播放列表末尾（已在列表里的不重复加）并播放，窗口切到前台；双击的正是当前在播放的文件时，重新载入一次（回到原位置） |
| 记住进度、延迟、音轨和字幕 | 每个文件分别记住上次的播放进度，以及手动选过的音轨 / 字幕（包括关闭字幕、外挂文件）；音频延迟和字幕延迟按音轨 / 字幕记（同一个视频里一条字幕准、一条不准也没关系，换轨时自动套用；旧版本按视频记的延迟会算到当时选中的那条上），再次打开时自动套用（Home 键从头开始）；看完的文件下次从头开始。记住的轨没了（例如外挂文件被删）就按首选语言规则选；没手动选过的文件一直按首选语言规则。全局设置 → 操作 里可分别关闭 |
| 视频参数 | 右键 → 视频参数（I），每秒刷新；播放列表里右键其它文件也能查看（后台读取，不影响播放），并列出全部音轨 / 字幕轨 |
| 悬浮控制栏 | 浮在画面底部，鼠标移动时出现、静止 2 秒后淡出（同时隐藏鼠标指针）；窗口和全屏下都一样，不占画面高度 |
| 检查更新 | 全局设置 → 关于：当前版本、构建号、播放内核版本、GitHub 地址和“检查更新”按钮。有新版本时自动下载到临时目录 `%TEMP%\HdrPlayer-update`（不弹保存位置），装完重新打开后自动删除，校验 SHA-256 后关闭播放器、静默安装并自动重新打开。下载时显示进度、大小和速度，进度条右边的 × 可以取消（关闭设置窗口也会取消），没下完的文件会删掉。只在点按钮时联网，跟随 Windows 的系统代理；便携版不自动更新 |
| 进度条预览 | 鼠标悬停在进度条上显示该位置的缩略图（后台另开一个不出画面的 mpv 实例，精确跳到最近的整秒截图，结果缓存；新图生成前旧图调暗显示）；仅本地文件，杜比视界 P5 只显示时间 |

## 快捷键

| 键 | 功能 |
|---|---|
| 空格 / 单击画面 / 中键 | 播放 / 暂停 |
| ← / → | 后退 / 前进 5 秒（可设置），跳转时显示控制栏 |
| Shift + ← / → | 后退 / 前进 30 秒 |
| ↑ / ↓ / 滚轮 | 音量 |
| M | 静音（音量条退到 0；再按一次回到 5%）。音量条拖到 0 也是静音，往右拖就解除 |
| F / 回车 / 双击 | 全屏；Esc 退出全屏 |

| Z / X | 字幕提前 / 延后（步进可设置，默认 100 ms；关闭字幕时不可用） |

## 已知限制

- 外部音轨请通过右键菜单 → 加载外部音轨，或拖到播放列表/控制栏上；拖到画面上会被 mpv 当作新视频加入播放列表。
- mpv 的画面是原生子窗口（HDR 需要 mpv 自己的交换链直接输出），WPF 内容不能直接叠在上面，所以悬浮控制栏是一个单独的透明小窗口，拖动主窗口时会跟随移动。
- 窗口化时画面四周留了 4 px 边距，用来拖动缩放窗口（原生子窗口会挡住窗口边缘的鼠标）。
- 音频输出设备只列出 WASAPI 设备。mpv 的设备列表里还有 OpenAL 等其它后端的 “Default (openal)” 之类条目，它们和“自动”一样指向系统默认设备，只是换了个输出后端，所以不再列出。
